## 2. 개요

### 2.1 목적
집보다 **사용자 모바일 앱(`zipboda-app`)** 개발 계획. 요구사항·화면·API 정의서(zipboda-web 대표 관리)를 근거로, 앱이 구현·소비하는 요구사항ID·화면ID(ZB-U-*)·API ID를 추적한다.

### 2.2 서비스 개요
LH·SH·GH·IH 공공 청약 정보 + 평면도(2D)·**WebGL 3D(1·3인칭 집구경)** + 인테리어 영감·쇼룸·가점·커뮤니티·마이페이지, 2차 가구 커머스. 앱은 **하단 5탭 내비(홈/쇼핑/커뮤니티/쇼룸/마이페이지, ZB-U-COM-02)** 기준.

### 2.3 범위 / 저장소 매핑
| 저장소 | 역할 | 비고 |
|--------|------|------|
| **zipboda-app** | 사용자 모바일 앱 | **본 문서 대상** |
| zipboda-web | 사용자 PC 웹 | 동일 도메인·공유 코드 |
| zipboda-api | 백엔드 API | 앱 소비 API 제공 |
| zipboda-admin | 운영 콘솔 | 운영 데이터 관리 |

## 3. 기술 스택 및 주요 결정 (권장, 착수 승인 필요)

> 검토 결함 app-Major(핵심 기술 결정 회피) 반영. 아래는 권장 확정안.

| 항목 | 결정(권장) | 근거 |
|------|-----------|------|
| 런타임 | **Expo + Dev Client(bare 확장 가능) + expo-router + TypeScript** | 네이티브 3D·결제·생체인증 확장 필요 → managed 순정이 아닌 dev client |
| 3D 엔진 | **expo-gl + three.js (glTF/GLB, Draco)** — WebView 미사용 | WebView 3D 성능 취약(검토 지적), 네이티브 GL로 결정 |
| 푸시 | **expo-notifications + FCM(Android)/APNs(iOS)** | 마감임박·구독 알림(REQ-US-004) |
| 빌드/배포 | **EAS Build/Submit**, 스토어(App Store/Play) 심사 파이프라인 | 검토 app-Major(스토어 배포 부재) |
| 서버 상태 | TanStack Query(응답 `{success,data,error}` 소비) | — |
| 공유 코드 | **pnpm workspace `@zipboda/shared`** (web과 API 타입·훅 공유) | 검토 app-Minor(공유 메커니즘) |
| 오프라인 | 캐시(AsyncStorage)+재시도 큐 | REQ-NF, 네트워크 불안정 |

### 3.1 디자인시스템 토큰(Figma)
Brand `#FFBA17` / Neutral `#1A1A1A`~`#F3F4F6` / Semantic(정보 `#2B7FFF`·성공 `#00BC7D`·경고 `#F59E0B`·오류 `#FF6467`) / Social(Kakao `#FEE500`·Naver `#03C75A`) / Inter+한글 400–900. web과 동일 토큰을 앱 테마로 매핑.

### 3.2 WebGL 3D(집구경) — 앱
ZB-U-PLAN-04를 expo-gl+three.js로 구현. 자산 메타 API-032 로딩, 1·3인칭 전환(ITF-013), **터치 제스처(드래그 회전·핀치 줌·이동)**, 저사양 2D 폴백(ZB-U-PLAN-03), 목표 30fps(REQ-NF-003).

## 7. 일정·공수 요약
- 총 공수(app): 약 **35 PW**(2차 5 PW 포함). 인력 가정: FE(app) 2명 + 3D 0.5명 + DevOps 0.3명.
- **크리티컬 패스:** S1 인증 → S2 청약/푸시 → **S4 3D(expo-gl)** → S7 스토어 배포. 3D는 S2에 PoC 병행.
- 스토어 심사 리드타임(iOS 심사 지연 가능)을 S7 일정에 버퍼로 반영.
